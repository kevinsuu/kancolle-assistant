# 關卡推薦配裝：本地驗收

本文件對應 `fix/flexible-stage-loadouts`。驗收的是推薦結果與 KC3 完整配裝計算；不需要實際出擊。

## 啟動與共同檢查

1. 在儲存庫根目錄執行 `yarn start`，開啟 KC3 戰略室的「關卡推薦」。
2. 按「重新同步」，再選海域及下表的攻略配置，產生推薦。
3. 裝備與艦娘名稱依 KC3 語系顯示；攻略名稱可能翻譯，括號中的 route ID 可協助對照日誌。
4. 每一案確認：使用持有艦與裝備、同一件裝備沒有重複、裝備可裝、制空／索敵／速度／先制對潛等硬條件通過。
5. 改動遊戲中的編成、裝備或庫存後，先重新同步再測。同一快照的相同請求會使用快取。

推薦會讀取**整個帳號**的裝備，包含其他艦娘身上的裝備。單純卸裝、換編隊不會限制可用庫存。
目前沒有用來指定必選艦或排除裝備的驗收控制項；下表艦艇是準備／比對範例，實際推薦可能選用帳號內更合適的艦艇。
低庫存、特殊競爭與失敗案例可用最後的自動測例驗證，不需要為了驗收廢棄裝備。

## 精算與失敗日誌

若要確認畫面未顯示的候選，檢查應用程式既有推薦日誌：

- `recommendation.completed` 的 `loadoutSearch`：`planCount`、`failedPlanCount`、`flexibleCarrierFleetCount`、`aswAllocationPlanCount`、`specialAssignmentPlanCount`、`emptyRegularSlotSolutionCount`。
- `recommendation.loadout-rerank-completed`：`candidateCount`、`sameFleetVariantCount`、`eligibleCandidateCount`、`surfaceAndAswCandidateCount`、`outcome`、`reasonCodes`、`elapsedMs`。同隊裝備替代案應在合併前計入 `sameFleetVariantCount`。
- `recommendation.oasw-loadout-validation-completed`：KC3 驗證過的先制對潛人數與最低需求。驗證全敗時應有 `OASW_INSUFFICIENT`，而非成功方案。
- `recommendation.combat-evaluation-failed`：KC3 計算器失敗時記錄原因。需要硬性先制對潛驗證的路線不得回退成未驗證結果。

搜尋仍有候選上限，不能解讀成全庫存窮舉或保證全域最佳解；也不是包含命中率、特殊攻擊發動率與道中損耗的完整戰鬥模擬。

## 可重複的最小測例

先執行 `yarn build:recommendation`，再執行：

```sh
node packages/recommendation-core/test/loadout-flexibility.test.js
```

這些測例建立記憶體中的假想庫存，驗證：

- 相同飛機庫存下，二攻二戰只有制空 75，但三戰一攻達 165，通過 150 門檻。
- 兩艘驅逐共用一件聲納時，分配一艘先制對潛，另一艘保留水面配裝。
- 三格艦只有兩件可用裝備時留空；缺少硬性必需的桶時仍然無解。
- 雷巡雙砲與雙魚雷的完整候選都被保留；裝備實例不重複。
- 三式彈、桶由不同承擔艦配置，包括同艦分別佔不同格。
- 同一艦隊的不同配裝進入精算候選池。

完整自動驗證使用 `yarn test:recommendation` 與 `yarn test:shell`。
